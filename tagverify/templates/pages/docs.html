API reference

Tag Verification API

REST over HTTPS, JSON or multipart in, JSON out. One endpoint does the scoring; the rest tell you what the service knows, how you are doing against your limit, and — for an admin — let you edit the tag catalog itself.

{# This callout used to sit third on the page, below the fold. It is the highest-consequence content here — misreading either field is how a non-compliant creative reaches a screen — so it goes first. #}

Two fields you must not ignore

  • present: null means uncertain, not false. The model declined to answer. Treat it as “needs a human” — reading it as absent is how a non-compliant creative slips through.
  • calibrated: false means that tag has not been measured against labelled images — or was measured, and the question has since been reworded. The verdict is an educated guess, and presenting it as a measurement is the failure mode this service exists to prevent.
{{ heading('authentication', 'Authentication') }}

Send your key in the x-api-key header; Authorization: Bearer … also works. Keys are issued in Admin and shown once — only a hash is stored, so a lost key cannot be recovered, only replaced.

An unknown key and a revoked key return byte-identical responses. That is deliberate: distinguishing them would tell an attacker which of their guesses had once been real.

{{ heading('analyze', 'Analyse a creative') }}
POST /api/v1/analyze key required

Accepts multipart, or JSON with media_base64 or media_url. Downscale images to 768px on the longest edge before sending — the model works at 224px, so nothing is lost and requests stay small. If you don’t, we do it for you.

Images and video use the same endpoint. Which one you sent is determined from the bytes, not from the field name, the filename or the Content-Type — so renaming a file changes nothing about which checks run. A video is sampled into up to {{ max_frames }} frames, each scored separately; a tag is present if it is present in any frame, and null if any frame was uncertain and none was present.

Request fields

media
Multipart file part. Any image Pillow can decode, up to {{ max_image_mb }}MB; or an MP4, MOV or WebM video up to {{ max_video_mb }}MB and {{ max_video_seconds }}s. image is accepted as an alias, and also takes either kind.
media_base64
JSON alternative to media. A bare base64 string; a data: prefix is accepted and stripped. image_base64 is accepted as an alias.
media_url
JSON alternative again. Must resolve to a public address — private, loopback and link-local targets are refused, and redirects are not followed. image_url is accepted as an alias.
tagsrequired
One or more known slugs. Repeat the field in multipart, or send an array in JSON. An unrecognised slug fails the whole request; see Errors.

Response

{{ code('ex-response', 'json', '{ "request_id": "5f1c...", "image_hash": "9a3f...", // sha256 of what you sent; never stored, either kind "image_bytes": 152341, "model": "' ~ (model or 'gemini-3.6-flash') ~ '", "packs_version": "' ~ (packs_version or '665544af9296') ~ '", "cached": false, "latency_ms": 612, "results": [{ "tag": "alcohol", "present": true, // true | false | null "score": 0.977, // the model\'s confidence in its own answer "confidence": "high", // high | medium | low, bucketed from score "decided_by": "vlm", "calibrated": false, // never measured, or measured then reworded "evidence": { "top_phrase": "a woman holding two steins of beer", // what it SAW "crop": null, // null from this scorer, never 0 "sigmoid": null } }], "uncalibrated_tags": ["alcohol"] // key omitted entirely when empty }', role='Response') }}

Response — video

Identical, plus two additions. An image response never carries either, so the presence of media is itself how you know frames were involved.

{{ code('ex-response-video', 'json', '{ "image_hash": "7c02...", // sha256 of the video file "image_bytes": 2418355, "cached": false, "latency_ms": 4180, "results": [{ "tag": "alcohol", "present": true, "score": 0.984, "confidence": "high", "decided_by": "vlm", "calibrated": false, "evidence": { "top_phrase": "a woman holding two steins of beer", "crop": null, "sigmoid": null, "frame": { "index": 2, "timestamp_s": 2.0 } // WHICH frame decided this } }], "media": { "kind": "video", "duration_s": 9.6, "frames_analyzed": 4, // frames actually scored "frames_considered": 4 // distinct scenes found; higher means partial coverage } }', role='Response') }}

Response fields

present
true, false, or null for uncertain. Three states, always. For a video this is decided across every sampled frame: true if any frame contains the tag, null if any frame was uncertain and none was present, false only when every frame was decided absent.
evidence.frame
Video only. index and timestamp_s of the frame this verdict came from — the score, crop, phrase and sigmoid all describe that one frame. Absent for images.
media.frames_considered
Video only. Distinct scenes the sampler found. When this exceeds frames_analyzed the per-request cap truncated, so coverage is partial — stated rather than left to be inferred.
score
The model’s own confidence in its own answer, 0–1. Nothing is compared against it — see How a verdict is decided. Use it to sort a review queue, never to decide one.
decided_by
vlm. Stored verdicts from before the current scorer may carry siglip or sigmoid_floor; the field stays open so an older row still parses.
calibrated
Whether this tag has been measured against labelled images, under the wording currently being asked. false means the verdict is a guess.
evidence.crop
[x0, y0, x1, y1] as fractions of width and height. null from the current scorer, which reports what it saw rather than which window scored highest.
evidence.sigmoid
null from the current scorer. It was an absolute resemblance, which a reading model does not produce. Null rather than zero: a zero would read as a measured absence rather than a question never asked.
cached
Whether the raw answers came from the cache. The decision rule is re-applied on every read, so a cached response always reflects the current rule.

Successful responses carry X-RateLimit-Limit and X-RateLimit-Remaining.

{{ heading('decisions', 'How a verdict is decided') }}

It is not decided here. Each tag’s name is put to the model as a question about the creative, and the model answers true, false or not sure. That answer is carried out to you unchanged. There is no threshold, no band and no veto.

This is the part most worth knowing, because it inverts what the older documentation described. A ranking model returned a similarity, which means nothing on its own — measured true positives ran from 0.028 to 0.902 — so a verdict had to be two cutoffs and an absolute-resemblance floor applied to it, and every tag needed calibrating before any of it meant anything. A reading model answers the question instead, so there is nothing left to band.

score is the model’s own reported confidence in its own answer, not a resemblance and not a probability of presence. Nothing enforces on it. It sorts a review queue by “answered, but barely”; it never decides, clears or blocks anything. Do not threshold it — a cutoff on a self-report is not the same quantity as a cutoff on a measurement, and treating it as one would reintroduce the rule this replaced.

confidence is that same number bucketed for triage: high at or above 0.85, medium at or above 0.60, low below it — and always low for an uncertain verdict, which has no margin to report.

present: null means uncertain, never false

It is the model declining to answer, and it is a request for a human. Collapsing it to false turns “we did not check” into “we checked and it is clean”, which is the single most damaging thing a consumer of this API can do with the response.

{{ heading('calibration', 'Calibration') }}

calibrated answers one question: has this tag ever been run against labelled images? It no longer describes a tuned threshold, because there is no threshold — it describes whether anyone has checked that the model answers this particular question correctly.

false does not mean the verdict is wrong. It means the verdict is an educated guess that has not been measured, and you should weigh it accordingly. It is exposed for exactly that reason, and it is never hardcoded true.

A measurement can go stale, and then it reports false again. packs_version fingerprints the questions being asked. If a tag was measured under one name and has since been renamed, the measurement no longer describes the answers being produced — so calibrated reverts to false rather than carrying a superseded number forward. Every tag reads false today for precisely this reason.

decision_version moves when any of this changes. Key your cache on it together with packs_version, or a verdict we have since revised will outlive the revision on your side.

{{ heading('tags', 'Managing tags') }}

The catalog is editable. These four endpoints are the JSON equivalent of the Tags tab in Admin — create a tag, rename it, retire it, or read the catalog as stored.

A written tag is live

There is no publish step. The model is asked its question per request, so the catalog is read from the database on every call — a tag saved a second ago is already being scored, and a reworded one is already being scored differently.

Every write still answers "pending_publish": true. That is a formality kept for callers that read it, not a state: nothing is pending. Rewording a tag does move packs_version, which sets calibrated: false on it until it is measured under the new name — so batch edits rather than trickling them. Editing a description moves nothing.

Authentication is different here

Two ways in, for two kinds of caller. The ordinary analyze key is refused — there is one such key and it belongs to the client asking “does this image contain alcohol?”, and letting that key also rewrite what alcohol means would be the wrong boundary.

A scoped key
For a service, such as DOOH admin. Send it in x-api-key exactly like any other key. It must carry the tags:write scope, which is set when the key is issued — tick “Can edit the tag catalog” in Admin, or pass --tags-write to dooh create-key. Issue a separate key rather than adding the scope to one already used for analysing. No CSRF header is needed: that defends a browser holding an ambient cookie, which this is not.
An admin session
For a person in a browser, and what Admin itself uses: the dooh_admin cookie plus an X-CSRF-Token header on anything that writes. A script can derive both from ADMIN_PASSWORD — both are HMAC-SHA256 over that secret, and the CSRF token is a fixed value, not a per-session nonce — but prefer a scoped key, which grants only this and not key issuance or threshold edits.

Deriving the session credentials by hand, if you need to:

{{ code('tags-auth', 'python', 'import hashlib, hmac, time PASSWORD = "..." # ADMIN_PASSWORD issued = str(int(time.time() * 1000)) # cookie is valid for 7 days cookie = issued + "." + hmac.new(PASSWORD.encode(), issued.encode(), hashlib.sha256).hexdigest() csrf = hmac.new(PASSWORD.encode(), b"csrf", hashlib.sha256).hexdigest() headers = {"Cookie": f"dooh_admin={cookie}", "X-CSRF-Token": csrf}') }}

With ADMIN_PASSWORD unset the session route has nothing to authenticate against and returns FORBIDDEN rather than opening. A scoped key still works — the two routes are independent.

Create a tag

POST /api/v1/tags admin session
slugrequired
Lowercase letters, digits and underscores, starting with a letter (^[a-z][a-z0-9_]*$). Trimmed and lowercased for you. It is permanent — it keys the tag’s eval images and its calibration row, it is the identifier a screen stores when it blocks the tag, and it cannot be changed later. Retiring a tag does not release it.
Required here. The profile admin form derives it from the label instead and lets you override it, which is why that form asks for a name and a sentence and nothing else. The two paths differ deliberately: an API caller already has an identifier in mind, or it would not be calling.
labelrequired
The tag’s name, and the whole of what the model is asked to look for. It reaches the model as - alcohol: Alcoholic content and nothing else about the tag does, so this field IS the detection. Also what a screen owner sees when choosing what to block. See below.
description
Optional. One line, shown to a screen owner beneath the name in the blocked-categories picker; a tag without one shows just its name. Not sent to the model, and editing it moves no fingerprint and re-scores nothing. Write it for the person choosing, not for the classifier.

positives, negatives, rationale and sigmoid_floor are gone. They were SigLIP’s question — it ranked an image against a pool of phrases and could not answer without one — and nothing has read them since that model was retired. They are ignored rather than rejected, so a caller still sending them gets a 200 and can drop them in its own time.

Returns 201 with the stored row, plus warnings and pending_publish. Warnings never block a save — they are advice about the name, and an empty list means none.

Not livestock feed, and not wild animals." }\'', role='Request') }} {{ code('tags-create-response', 'json', '{ "slug": "pet_supplies", "label": "Pet supplies", "description": "Pet food, treats, toys, bedding and accessories for domestic pets. "warnings": [], // A formality: there is no publish step. The tag is live at the next request. "pending_publish": true }', role='Response') }}

Update a tag

PATCH /api/v1/tags/{slug} admin session

Despite the verb, this is a full replace, not a partial update. Every field POST requires must be sent; anything you omit is not preserved.

The slug comes from the path and cannot be changed — a rename would strand the tag’s eval images and thresholds. Returns 200 with the same body shape as create. 404 if the slug does not exist.

Retire a tag

DELETE /api/v1/tags/{slug} admin session

Retires, never deletes. Returns 200 (not 204) with the row, now "status": "retired". Safe to repeat.

The row survives so the slug keeps its labelled eval images and measured thresholds, and a screen that still blocks the tag keeps working until it is next saved. The consequence worth knowing: the slug stays reserved — so POSTing it again returns 400, not a fresh tag.

Read the catalog as stored

GET /api/v1/tags/managed admin session

Every row including retired ones, with status and authorship. This is not the same as GET /api/v1/tags: that one is the public catalog, active tags only, carrying a calibrated flag instead.

{{ code('tags-managed-response', 'json', '{ "count": 24, "tags": [{ "slug": "alcohol", "label": "Alcohol", "description": "Beer, wine and spirits...", "status": "active", "updated_at": "...", "updated_by": "admin" }] }', role='Response') }}

What makes a tag work

The name is the whole of the detection. The model receives one line per category — - alcohol: Alcoholic content — and nothing else about the tag. Everything about how to decide is in the system instruction: judge only what is visibly depicted, read labels and packaging, count a category present if it appears anywhere however small, and answer null rather than guess. The catalog supplies only which categories.

So a tag is as good as its name, and unlike a threshold there is nothing to tune afterwards. Two rules:

  • Name the category, not the object. “Alcoholic content” reads as a category a screen owner might block; “dog” is a word. “Dogs and puppies” is better than both for the same three syllables.
  • Say it the way you would to someone seeing it for the first time. The same name is shown to the screen owner choosing what to block, so if it does not tell them what they are blocking, it is not telling the model either.

What you can no longer say

A name cannot carry a boundary. There is nowhere to write “packaged juice counts as a sugary drink” or “alcohol-free 0.0% beer does not”, so the model decides those cases on its own and its answer can move when the model version does. Where two categories overlap — junk food and restaurant dining, protein supplements and pharmaceuticals — expect both to fire on the ambiguous creative.

The remaining lever is the name. A tag that misfires is fixed by renaming it, which correctly re-keys the verdicts decided under the old name.

Renaming a tag moves packs_version, which is correct: verdicts decided under the old name stop being served under the new one. Editing a description does not, because it is not part of the question. The catalog is capped at 100 active tags, because every analyze call sends the whole catalog.

Errors

Validation failures return 400 BAD_REQUEST and the message is written to be shown to whoever typed it — e.g. “A name is required — it is what the model is asked to look for, and what a screen owner sees.” Missing session or CSRF token is 403 FORBIDDEN; an unknown slug on update or retire is 404 NOT_FOUND. See Errors.

Called with a scoped key, these count against that key’s rate limit like any other request — authenticating a key always charges it. Called with an admin session they are not limited at all.

{{ heading('other', 'Other endpoints') }}
GET /api/v1/tags key required

The tag catalog, with a calibrated flag per tag. Thresholds themselves are never exposed here.

GET /api/v1/usage key required

This key’s traffic today, and its per-minute limit.

GET /api/v1/health no key

Database and inference status, reported separately. Always returns 200 with the status in the body — so a monitor can treat any non-200 as “the app itself is down” rather than having to parse degradation out of a status code.
