API reference

Tag Verification API

REST over HTTPS, JSON or multipart in, JSON out. One endpoint does the scoring; the rest tell you what the service knows, how you are doing against your limit, and — for an admin — let you edit the tag catalog itself.

{# This callout used to sit third on the page, below the fold. It is the highest-consequence content here — misreading either field is how a non-compliant creative reaches a screen — so it goes first. #}

Two fields you must not ignore

  • present: null means uncertain, not false. The score fell between the thresholds. Treat it as “needs a human” — reading it as absent is how a non-compliant creative slips through.
  • calibrated: false means that tag’s thresholds were never measured against labelled images. The verdict is an educated guess, and presenting it as a measurement is the failure mode this service exists to prevent.
{{ heading('authentication', 'Authentication') }}

Send your key in the x-api-key header; Authorization: Bearer … also works. Keys are issued in Admin and shown once — only a hash is stored, so a lost key cannot be recovered, only replaced.

An unknown key and a revoked key return byte-identical responses. That is deliberate: distinguishing them would tell an attacker which of their guesses had once been real.

{{ heading('analyze', 'Analyse a creative') }}
POST /api/v1/analyze key required

Accepts multipart, or JSON with media_base64 or media_url. Downscale images to 768px on the longest edge before sending — the model works at 224px, so nothing is lost and requests stay small. If you don’t, we do it for you.

Images and video use the same endpoint. Which one you sent is determined from the bytes, not from the field name, the filename or the Content-Type — so renaming a file changes nothing about which checks run. A video is sampled into up to {{ max_frames }} frames, each scored separately; a tag is present if it is present in any frame, and null if any frame was uncertain and none was present.

Request fields

media
Multipart file part. Any image Pillow can decode, up to {{ max_image_mb }}MB; or an MP4, MOV or WebM video up to {{ max_video_mb }}MB and {{ max_video_seconds }}s. image is accepted as an alias, and also takes either kind.
media_base64
JSON alternative to media. A bare base64 string; a data: prefix is accepted and stripped. image_base64 is accepted as an alias.
media_url
JSON alternative again. Must resolve to a public address — private, loopback and link-local targets are refused, and redirects are not followed. image_url is accepted as an alias.
tagsrequired
One or more known slugs. Repeat the field in multipart, or send an array in JSON. An unrecognised slug fails the whole request; see Errors.

{{ code('ex-python', 'python', 'import httpx with open("creative.jpg", "rb") as fh: response = httpx.post( "https://your-app/api/v1/analyze", headers={"x-api-key": "dooh_live_..."}, files={"image": fh}, data={"tags": ["alcohol", "gym_fitness"]}, ) for verdict in response.json()["results"]: if verdict["present"] is None: print(f"{verdict[\'tag\']}: needs a human") # NOT absent elif verdict["present"]: print(f"{verdict[\'tag\']}: present")') }}

Response

{{ code('ex-response', 'json', '{ "request_id": "5f1c...", "image_hash": "9a3f...", // sha256 of what you sent; never stored, either kind "image_bytes": 152341, "model": "' ~ (model or 'google/siglip2-base-patch16-224') ~ '", "packs_version": "' ~ (packs_version or '1a2db18ba940') ~ '", "cached": false, "latency_ms": 612, "results": [{ "tag": "alcohol", "present": true, // true | false | null "score": 0.977, "confidence": "high", // high | medium | low "decided_by": "siglip", // siglip | sigmoid_floor "calibrated": false, "evidence": { "top_phrase": "a glass of beer with foam", "crop": [0.0, 0.5, 0.5, 1.0], // where it was found, as 0-1 fractions "sigmoid": 0.028 } }], "uncalibrated_tags": ["alcohol"] // key omitted entirely when empty }') }}

Response — video

Identical, plus two additions. An image response never carries either, so the presence of media is itself how you know frames were involved.

{{ code('ex-response-video', 'json', '{ "image_hash": "7c02...", // sha256 of the video file "image_bytes": 2418355, "cached": false, "latency_ms": 4180, "results": [{ "tag": "alcohol", "present": true, "score": 0.984, "confidence": "high", "decided_by": "siglip", "calibrated": false, "evidence": { "top_phrase": "a glass of beer with foam", "crop": [0.0, 0.5, 0.5, 1.0], "sigmoid": 0.031, "frame": { "index": 2, "timestamp_s": 2.0 } // WHICH frame decided this } }], "media": { "kind": "video", "duration_s": 9.6, "frames_analyzed": 4, // frames actually scored "frames_considered": 4 // distinct scenes found; higher means partial coverage } }') }}

Response fields

present
true, false, or null for uncertain. Three states, always. For a video this is decided across every sampled frame: true if any frame contains the tag, null if any frame was uncertain and none was present, false only when every frame was decided absent.
evidence.frame
Video only. index and timestamp_s of the frame this verdict came from — the score, crop, phrase and sigmoid all describe that one frame. Absent for images.
media.frames_considered
Video only. Distinct scenes the sampler found. When this exceeds frames_analyzed the per-request cap truncated, so coverage is partial — stated rather than left to be inferred.
score
Softmax mass on the tag’s positive prompts, 0–1. This is the number the thresholds are compared against.
decided_by
siglip for a normal threshold decision, sigmoid_floor when the absolute-resemblance veto fired — see How a verdict is decided.
calibrated
Whether this tag’s thresholds were measured against labelled images. false means the verdict is a guess.
evidence.crop
[x0, y0, x1, y1] as fractions of width and height — the window that scored highest, suitable for drawing a box on the original.
evidence.sigmoid
Absolute resemblance to the tag, independent of the comparison pool. Only decisive when it falls below the floor.
cached
Whether the raw scores came from the cache. Thresholds are re-applied on every read, so a cached response still reflects the current thresholds.

Successful responses carry X-RateLimit-Limit and X-RateLimit-Remaining.

{{ heading('decisions', 'How a verdict is decided') }}

Each tag has a pool of positive phrases, hand-written hard negatives, and shared distractors. A softmax across that pool answers the relative question — which of these best describes the image — and score is the probability mass that landed on the positives.

A sigmoid on the positives alone answers the absolute question: does this image resemble the tag at all? That is checked first, as a veto. Softmax must sum to 1, so a photo of a mountain can hand half its mass to “a glass of beer” purely by beating equally-irrelevant options. When the veto fires, decided_by is sigmoid_floor.

Otherwise the bands are inclusive at both edges:

present
score ≥ threshold_high
absent
score ≤ threshold_low
null
anything between the two — uncertain, and yours to escalate
{{ heading('calibration', 'Calibration') }}

Thresholds are per-tag and live in the database, so they can be retuned without redeploying the model. A tag is calibrated: true only after those numbers were measured against labelled images — at least eight per class. Until then the thresholds are the provisional guesses shipped in the prompt pack, and the field says so.

packs_version fingerprints the prompt pack. If a threshold was calibrated against a different pack than the one currently serving, the threshold is still applied — it is the best available — but calibrated reverts to false, because it no longer describes the scores being produced.

{{ heading('tags', 'Managing tags') }}

The catalog is editable. These four endpoints are the JSON equivalent of the Tags tab in Admin — create a tag, rewrite its phrases, retire it, or read the catalog as stored rather than as the model currently has it.

Writing a tag does not publish it

The model loads every prompt once, at startup. A tag written here is a database row and nothing more until the pack is published — which is why every write below answers "pending_publish": true.

Publish with dooh export-packs --push. That writes the pack and pushes it into the running model, which re-encodes the prompts in place. No restart. Until you do, GET /api/v1/tags and every analyze call keep using the old catalog — that endpoint is served from what the model holds, not from what you just wrote.

Authentication is different here

Two ways in, for two kinds of caller. The ordinary analyze key is refused — there is one such key and it belongs to the client asking “does this image contain alcohol?”, and letting that key also rewrite what alcohol means would be the wrong boundary.

A scoped key
For a service, such as DOOH admin. Send it in x-api-key exactly like any other key. It must carry the tags:write scope, which is set when the key is issued — tick “Can edit the tag catalog” in Admin, or pass --tags-write to dooh create-key. Issue a separate key rather than adding the scope to one already used for analysing. No CSRF header is needed: that defends a browser holding an ambient cookie, which this is not.
An admin session
For a person in a browser, and what Admin itself uses: the dooh_admin cookie plus an X-CSRF-Token header on anything that writes. A script can derive both from ADMIN_PASSWORD — both are HMAC-SHA256 over that secret, and the CSRF token is a fixed value, not a per-session nonce — but prefer a scoped key, which grants only this and not key issuance or threshold edits.

Deriving the session credentials by hand, if you need to:

{{ code('tags-auth', 'python', 'import hashlib, hmac, time PASSWORD = "..." # ADMIN_PASSWORD issued = str(int(time.time() * 1000)) # cookie is valid for 7 days cookie = issued + "." + hmac.new(PASSWORD.encode(), issued.encode(), hashlib.sha256).hexdigest() csrf = hmac.new(PASSWORD.encode(), b"csrf", hashlib.sha256).hexdigest() headers = {"Cookie": f"dooh_admin={cookie}", "X-CSRF-Token": csrf}') }}

With ADMIN_PASSWORD unset the session route has nothing to authenticate against and returns FORBIDDEN rather than opening. A scoped key still works — the two routes are independent.

Create a tag

POST /api/v1/tags admin session
slugrequired
Lowercase letters, digits and underscores, starting with a letter (^[a-z][a-z0-9_]*$). Trimmed and lowercased for you. It is permanent — it keys the tag’s eval images and its measured thresholds, and it cannot be changed later.
labelrequired
What a screen owner sees when choosing what to block.
descriptionrequired
One line, shown to a screen owner — and, under the VLM scorer, the whole of what the model is asked. Name the thing, name its boundary, and say what does not count.
positivesSigLIP only
At least 5 phrases describing what you are hunting; 8 or more is where tags start behaving. Required only while the SigLIP scorer is running, which ranks an image against them. The VLM scorer reads the description instead and never sees these, so a tag authored for it may omit them.
negativesSigLIP only
At least 6 phrases naming what gets mistaken for it. Under SigLIP these do most of the work — see below. Ignored by the VLM scorer, on the same terms as positives.
rationale
Why these negatives. Optional, and worth writing: it is what stops the next person undoing a fix they cannot see.
sigmoid_floor
Between 0 and 1. Leave it out. It is measured by calibration, not authored, and omitting it on an update preserves whatever was measured.

Returns 201 with the stored row, plus warnings and pending_publish. Warnings never block a save — they are advice about phrasing, and an empty list means none.

{{ code('tags-create', 'shell', 'curl -X POST https://your-app/api/v1/tags \\ -H "Cookie: dooh_admin=$COOKIE" \\ -H "X-CSRF-Token: $CSRF" \\ -H "Content-Type: application/json" \\ -d \'{ "slug": "pet_supplies", "label": "Pet supplies", "description": "Pet food, toys and accessories.", "positives": ["a bag of dog food", "a cat sitting in a pet carrier", "..."], "negatives": ["a bag of rice", "a wild animal in a forest", "..."] }\'') }} {{ code('tags-create-response', 'json', '{ "slug": "pet_supplies", "label": "Pet supplies", "description": "Pet food, toys and accessories.", "positives": ["a bag of dog food", "..."], "negatives": ["a bag of rice", "..."], "rationale": null, "sigmoid_floor": null, "status": "active", "updated_at": "2026-08-26T09:41:12.402831+00:00", "updated_by": "admin", // Advice, not errors. The tag saved. "warnings": ["Only 6 positives. 8+ is where tags start behaving."], // Written, not live. Run `dooh export-packs --push`. "pending_publish": true }') }}

Update a tag

PATCH /api/v1/tags/{slug} admin session

Despite the verb, this is a full replace, not a partial update. Every field POST requires must be sent; anything you omit is not preserved. The one exception is sigmoid_floor, which is kept when absent because it is measured rather than typed.

The slug comes from the path and cannot be changed — a rename would strand the tag’s eval images and thresholds. Returns 200 with the same body shape as create. 404 if the slug does not exist.

Retire a tag

DELETE /api/v1/tags/{slug} admin session

Retires, never deletes. Returns 200 (not 204) with the row, now "status": "retired". Safe to repeat.

The row survives so the slug keeps its labelled eval images and measured thresholds, and a screen that still blocks the tag keeps working until it is next saved. Two consequences worth knowing: a retired tag’s phrases become free for another tag to use, but its slug stays reserved — so POSTing it again returns 400, not a fresh tag.

Publish

POST /api/v1/tags/publish admin session or tags:write

Makes every written tag live, with no restart. Exports the catalog to the pack file and pushes those bytes into the running model, which re-encodes its prompts in place. The remote half of dooh export-packs --push, and the same code underneath.

It publishes the whole catalog, not one tag. A pack is a single artifact with a single fingerprint, so there is no such thing as publishing one tag — and this will take everyone’s pending edits live, not just yours.

Not cheap, so batch your edits and publish once: re-encoding takes seconds and moves packs_version, which makes every tag report calibrated: false until it is measured again.

{{ code('tags-publish-response', 'json', '{ "packs_version": "2d9b089ea283", // the NEW fingerprint; every verdict is stamped with it "count": 22, "tags": ["alcohol", "automotive", "..."] // what the model now actually holds }') }}

Returns 409 NOT_CONFIGURED when no shared secret is set between the two tiers — publishing is off rather than open, and retrying will not help. 503 if the model is still waking, which is worth retrying.

Read the catalog as stored

GET /api/v1/tags/managed admin session

Every row including retired ones, with the prompts. This is not the same as GET /api/v1/tags: that one is the public catalog as the model currently has it and never exposes prompts, this one is the database. When they disagree, something is written but not published.

{{ code('tags-managed-response', 'json', '{ "count": 21, "tags": [{ "slug": "alcohol", "label": "Alcohol", "positives": ["..."], "negatives": ["..."], "status": "active", "updated_at": "...", "updated_by": "admin" }] }') }}

What makes a tag work

The phrases are the whole of the detection. The model is zero-shot: it compares the image against these words and nothing else, so a tag is only as good as its wording. Two rules, both measured:

  • Mirror the phrasing. If a positive says “a scoop of X”, a negative should say “a scoop of Y”. With only “a tin of baby formula” as a negative, infant formula scored 0.709 for protein_supplements — wrongly present. Adding “a scoop of baby formula milk powder” dropped it to 0.224 while real whey stayed at 0.999.
  • Name the confusable neighbour, not random things. The model already scores a mountain near zero for alcohol; a negative that is obviously different teaches it nothing. Half your negatives should be things a careless human might mislabel.

A phrase already used as another active tag’s positive is refused. Two tags sharing a phrase lose it from both their comparison pools, which weakens the competition each relies on. The catalog is also capped at 30 active tags, because every analyze call sends the whole catalog.

Errors

Validation failures return 400 BAD_REQUEST and the message is written to be shown to whoever typed it — e.g. “A tag needs at least 5 positives — this one has 4.” Missing session or CSRF token is 403 FORBIDDEN; an unknown slug on update or retire is 404 NOT_FOUND. See Errors.

Called with a scoped key, these count against that key’s rate limit like any other request — authenticating a key always charges it. Called with an admin session they are not limited at all.

{{ heading('other', 'Other endpoints') }}
GET /api/v1/tags key required

The tag catalog, with a calibrated flag per tag. Thresholds themselves are never exposed here.

GET /api/v1/usage key required

This key’s traffic today, and its per-minute limit.

GET /api/v1/health no key

Database and inference status, reported separately. Always returns 200 with the status in the body — so a monitor can treat any non-200 as “the app itself is down” rather than having to parse degradation out of a status code.

Every failure returns { "error": "CODE", "message": "…" }, so you can branch on the code rather than matching prose.
