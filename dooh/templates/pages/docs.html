API reference

Tag Verification API

REST over HTTPS, JSON or multipart in, JSON out. One endpoint does the work; the other three tell you what the service knows and how you are doing against your limit.

{# This callout used to sit third on the page, below the fold. It is the highest-consequence content here — misreading either field is how a non-compliant creative reaches a screen — so it goes first. #}

Two fields you must not ignore

  • present: null means uncertain, not false. The score fell between the thresholds. Treat it as “needs a human” — reading it as absent is how a non-compliant creative slips through.
  • calibrated: false means that tag’s thresholds were never measured against labelled images. The verdict is an educated guess, and presenting it as a measurement is the failure mode this service exists to prevent.
{{ heading('authentication', 'Authentication') }}

Send your key in the x-api-key header; Authorization: Bearer … also works. Keys are issued in Admin and shown once — only a hash is stored, so a lost key cannot be recovered, only replaced.

An unknown key and a revoked key return byte-identical responses. That is deliberate: distinguishing them would tell an attacker which of their guesses had once been real.

{{ heading('analyze', 'Analyse a creative') }}
POST /api/v1/analyze key required

Accepts multipart, or JSON with media_base64 or media_url. Downscale images to 768px on the longest edge before sending — the model works at 224px, so nothing is lost and requests stay small. If you don’t, we do it for you.

Images and video use the same endpoint. Which one you sent is determined from the bytes, not from the field name, the filename or the Content-Type — so renaming a file changes nothing about which checks run. A video is sampled into up to {{ max_frames }} frames, each scored separately; a tag is present if it is present in any frame, and null if any frame was uncertain and none was present.

Request fields

media
Multipart file part. Any image Pillow can decode, up to {{ max_image_mb }}MB; or an MP4, MOV or WebM video up to {{ max_video_mb }}MB and {{ max_video_seconds }}s. image is accepted as an alias, and also takes either kind.
media_base64
JSON alternative to media. A bare base64 string; a data: prefix is accepted and stripped. image_base64 is accepted as an alias.
media_url
JSON alternative again. Must resolve to a public address — private, loopback and link-local targets are refused, and redirects are not followed. image_url is accepted as an alias.
tagsrequired
One or more known slugs. Repeat the field in multipart, or send an array in JSON. An unrecognised slug fails the whole request; see Errors.

Response — video

Identical, plus two additions. An image response never carries either, so the presence of media is itself how you know frames were involved.

{{ code('ex-response-video', 'json', '{ "image_hash": "7c02...", // sha256 of the video file "image_bytes": 2418355, "cached": false, "latency_ms": 4180, "results": [{ "tag": "alcohol", "present": true, "score": 0.984, "confidence": "high", "decided_by": "siglip", "calibrated": false, "evidence": { "top_phrase": "a glass of beer with foam", "crop": [0.0, 0.5, 0.5, 1.0], "sigmoid": 0.031, "frame": { "index": 2, "timestamp_s": 2.0 } // WHICH frame decided this } }], "media": { "kind": "video", "duration_s": 9.6, "frames_analyzed": 4, // frames actually scored "frames_considered": 4 // distinct scenes found; higher means partial coverage } }') }}

Response fields

present
true, false, or null for uncertain. Three states, always. For a video this is decided across every sampled frame: true if any frame contains the tag, null if any frame was uncertain and none was present, false only when every frame was decided absent.
evidence.frame
Video only. index and timestamp_s of the frame this verdict came from — the score, crop, phrase and sigmoid all describe that one frame. Absent for images.
media.frames_considered
Video only. Distinct scenes the sampler found. When this exceeds frames_analyzed the per-request cap truncated, so coverage is partial — stated rather than left to be inferred.
score
Softmax mass on the tag’s positive prompts, 0–1. This is the number the thresholds are compared against.
decided_by
siglip for a normal threshold decision, sigmoid_floor when the absolute-resemblance veto fired — see How a verdict is decided.
calibrated
Whether this tag’s thresholds were measured against labelled images. false means the verdict is a guess.
evidence.crop
[x0, y0, x1, y1] as fractions of width and height — the window that scored highest, suitable for drawing a box on the original.
evidence.sigmoid
Absolute resemblance to the tag, independent of the comparison pool. Only decisive when it falls below the floor.
cached
Whether the raw scores came from the cache. Thresholds are re-applied on every read, so a cached response still reflects the current thresholds.

Successful responses carry X-RateLimit-Limit and X-RateLimit-Remaining.

{{ heading('decisions', 'How a verdict is decided') }}

Each tag has a pool of positive phrases, hand-written hard negatives, and shared distractors. A softmax across that pool answers the relative question — which of these best describes the image — and score is the probability mass that landed on the positives.

A sigmoid on the positives alone answers the absolute question: does this image resemble the tag at all? That is checked first, as a veto. Softmax must sum to 1, so a photo of a mountain can hand half its mass to “a glass of beer” purely by beating equally-irrelevant options. When the veto fires, decided_by is sigmoid_floor.

Otherwise the bands are inclusive at both edges:

present
score ≥ threshold_high
absent
score ≤ threshold_low
null
anything between the two — uncertain, and yours to escalate
{{ heading('calibration', 'Calibration') }}

Thresholds are per-tag and live in the database, so they can be retuned without redeploying the model. A tag is calibrated: true only after those numbers were measured against labelled images — at least eight per class. Until then the thresholds are the provisional guesses shipped in the prompt pack, and the field says so.

packs_version fingerprints the prompt pack. If a threshold was calibrated against a different pack than the one currently serving, the threshold is still applied — it is the best available — but calibrated reverts to false, because it no longer describes the scores being produced.

{{ heading('other', 'Other endpoints') }}
GET /api/v1/tags key required

The tag catalog, with a calibrated flag per tag. Thresholds themselves are never exposed here.

GET /api/v1/usage key required

This key’s traffic today, and its per-minute limit.

GET /api/v1/health no key

Database and inference status, reported separately. Always returns 200 with the status in the body — so a monitor can treat any non-200 as “the app itself is down” rather than having to parse degradation out of a status code.

{{ heading('errors', 'Errors') }}

Every failure returns { "error": "CODE", "message": "…" }, so you can branch on the code rather than matching prose.
